# 학습 노트

이 도구를 만들면서 나눈 질문과 답을 정리한 것입니다.
모든 숫자는 실제로 이 코드를 돌려서 얻은 값이고, 아래 설정을 기본으로 합니다.

```
데이터셋 moons · 점 100개 · 노이즈 0.1 · 시드 1 · MLP(2, [16,16,1]) · ReLU · lr 0.5
```

---

## 1. 최종 출력 뉴런의 값은 무엇인가

**score(점수)** 입니다. 확률이 아닙니다.

출력 뉴런만 활성화 함수가 없어서([nn.js](src/nn.js) 의 마지막 레이어 `nonlin: false`),
`w·x + b` 가 그대로 나옵니다. 범위 제한이 없어 대략 −4 ~ +4 사이의 아무 값이나 나옵니다.

| score | 뜻 |
| --- | --- |
| `> 0` | +1(파랑)로 예측 |
| `< 0` | −1(빨강)로 예측 |
| `= 0` | 결정 경계. 데이터 화면에서 파랑/빨강이 만나는 선 |
| `\|score\| ≥ 1` | 여유 있게 맞힘. 손실 0 |
| `\|score\| < 1` | 맞혔어도 아슬아슬해서 손실이 남음 |

정답률은 부호만 봅니다([trainer.js](src/trainer.js) 의 `scores[i] > 0 ? 1 : -1`).

### 크기에 의미가 있는 이유: hinge loss

손실이 `relu(1 − y × score)` 라서, 부호만 맞아서는 부족하고
**정답 쪽으로 1 이상 넘어가야** 손실이 0이 됩니다.

```
y=+1, score= 2.5  →  relu(1-2.5) = 0      만족
y=+1, score= 0.3  →  relu(0.7)   = 0.7    맞혔지만 더 밀어냄
y=+1, score=-1.2  →  relu(2.2)   = 2.2    틀렸고 크게 벌점
```

그래서 정답률이 100%가 된 뒤에도 손실은 계속 줄어듭니다.
학습 곡선에서 초록선이 천장에 붙은 뒤에도 노란선이 내려가는 이유입니다.

실측 (시드 1):

```
학습 전   가장 애매한 점  score  0.001    |score| < 1 인 점: 59 / 100
학습 후   가장 애매한 점  score -1.008    |score| < 1 인 점:  0 / 100
          가장 확신하는 점 score  3.735
```

## 2. 파라미터는 어떤 방향으로 조절되는가

**모든 grad는 출력 score에서 시작해 거꾸로 흐릅니다.** 다른 출발점은 없습니다.

### 1단계 — 손실이 score에게 내리는 주문

```
y·score < 1  (마진 미달)  →  ∂L/∂score = −y/n
y·score ≥ 1  (여유 있음)  →  ∂L/∂score = 0
```

실측 (첫 스텝, n=100):

```
y=-1  score= 0.867  hinge=1.867  dL/dscore= +0.01000    ← -y/n
y=+1  score= 0.230  hinge=0.770  dL/dscore= -0.01000
y=+1  score= 2.124  hinge=0.000  dL/dscore=  0.00000    ← 신호 없음
```

grad는 "손실이 늘어나는 방향"이고 업데이트는 반대로 가므로,
`−y/n` 은 결국 **언제나 자기 라벨 쪽으로 score를 밀라**는 뜻입니다.

이미 마진을 채운 점은 grad가 정확히 0이라 아무 주문도 하지 않습니다.
첫 스텝에서 100개 중 74개만 신호를 보내고, 학습이 끝나면 0개가 됩니다.

### 2단계 — 파라미터로 분배

```
∂L/∂w  =  ∂L/∂score  ×  ∂score/∂w
          └ 모두가 공유 ┘   └ 파라미터마다 다름 ┘
```

앞 항은 337개 파라미터가 전부 똑같이 받습니다.
달라지는 건 "내가 score에 얼마나 기여했나" 뿐입니다.

출력 뉴런 `w[0]` 으로 검증:

```
실제 grad            = -0.06079649
Σ(dL/ds × 활성값) + L2 = -0.06079649     소수점 8자리 일치
```

곱셈이라는 게 중요합니다. 어떤 뉴런이 그 점에서 활성값 0을 냈다면(ReLU가 죽은 경우)
곱해서 0 → 그 파라미터는 이번 스텝에 안 움직입니다.
**책임이 있는 만큼만 고쳐진다**가 곱셈으로 자동 구현됩니다.

### 3단계 — 은닉층으로

[engine.js](src/engine.js) 의 `mul` 한 줄이 이 전부를 처리합니다.

```js
out._backward = () => {
  this.grad  += other.data * out.grad;   // 내 grad = 상대 값 × 위에서 온 grad
  other.grad += this.data  * out.grad;
};
```

출력 가중치가 큰 뉴런일수록 강한 수정 압력을 받습니다.
네트워크 화면의 역전파 단계에서 노란 선이 출력 쪽에서 굵고 입력으로 갈수록 가는 이유입니다.

### 한 스텝의 요약

> 마진을 못 채운 74개 점을 골라, 각자 자기 라벨 쪽으로 score를 밀어라.
> 그 밀기에 기여한 파라미터들에게만, 기여한 비율만큼 수정을 배분하라.

실측: 신호를 보낸 74개 중 **66개**의 score가 정답 쪽으로 움직임 (8개는 반대).
반대로 간 8개가 정상입니다. gradient descent가 보장하는 건 개별 점이 아니라 **평균 손실**입니다.

## 3. 왜 모든 grad는 "손실이 늘어나는 방향"인가

미분의 정의 그 자체입니다. `∂L/∂w` = "w를 1 늘리면 L이 얼마나 늘어나는가".

```
grad > 0  →  w를 늘리면 L 증가  →  줄이려면 w를 줄여야
grad < 0  →  w를 늘리면 L 감소  →  줄이려면 w를 늘려야
```

`w -= lr * grad` 가 부호에 상관없이 자동으로 맞아떨어집니다.

실측:

```
p[  0] grad= +0.014249  |  grad 방향 +ε → L 증가  |  반대 -ε → L 감소
p[120] grad= -0.000113  |  grad 방향 +ε → L 증가  |  반대 -ε → L 감소
```

### "증가" 기준인 이유는 코드 한 줄

[engine.js](src/engine.js) 의 `backward()`:

```js
this.grad = 1;        // ∂L/∂L = 1
```

이 씨앗이 연쇄법칙을 타고 내려가면서 모든 노드의 grad가 `∂L/∂(그 노드)` 라는 의미를 갖습니다.
`-1` 을 심으면 전부 부호가 뒤집혀 "감소 방향"이 되고, 업데이트는 `+=` 가 됩니다. 결과는 동일.

### 왜 하필 grad 방향인가

손실을 줄이는 방향은 무수히 많습니다(grad 반대편 반구 전체).
`−∇L` 을 쓰는 이유는 **같은 크기의 걸음으로 가장 많이 줄이는 방향**이기 때문입니다.
방향 `u` 로 갈 때 변화율은 `∇L · u` 이고, 코시-슈바르츠에 의해 `u ∥ ∇L` 일 때 최대.

크기에도 의미가 있습니다. 가파른 파라미터는 크게, 평평한 파라미터는 작게 움직입니다.

### 중요 단서: 국소적으로만 참

작은 걸음에서는 예측이 정확합니다.

```
걸음 0.00001:  +grad → +1.31e-5    -grad → -1.31e-5
걸음 0.0001 :  +grad → +1.31e-4    -grad → -1.31e-4    정확히 10배
```

큰 걸음에서는 깨집니다. `−grad` 방향인데도 손실이 늘어납니다.

```
lr=0.5  →  L=0.697  감소
lr=2    →  L=0.680  감소
lr=5    →  L=1.233  증가    ← 골짜기를 넘어감
lr=100  →  L=317.3  증가
```

**방향은 grad가 알려주지만 얼마나 갈지는 알려주지 않습니다.** 그게 학습률의 역할입니다.

## 4. grad는 뭐에 대한 뭐의 기울기인가

**∂L/∂x — 손실 L을 그 노드의 값 x로 미분한 값.**

분자는 항상 손실 하나로 고정, 분모만 노드마다 바뀝니다.

| 노드 | grad의 의미 |
| --- | --- |
| 가중치 `w` | ∂L/∂w |
| 출력 `score` | ∂L/∂score |
| 은닉 활성값 `a` | ∂L/∂a |
| 입력 `x`, `y` | ∂L/∂x |
| 중간 임시 노드 | ∂L/∂(그 값) |

### 흔한 오해

`w.grad` 는 "그 뉴런의 출력을 w로 미분한 것"이 아닙니다.
그건 연쇄법칙의 한 조각일 뿐이고, grad는 위에서 내려온 신호까지 곱해진 최종 결과입니다.

### 분자는 backward()를 부른 노드가 정한다

```
loss.backward()   →  p[5].grad = 0.237947   (= ∂L/∂w)   중심차분 검증 일치
score.backward()  →  p[5].grad = 1.159095   (= ∂score/∂w)
```

같은 파라미터인데 값이 다릅니다. grad는 파라미터에 붙박이로 딸린 성질이 아니라
**무엇을 기준으로 쟀느냐**에 따라 달라집니다.

입력도 grad를 갖습니다 (`x.grad = -1.205`, `y.grad = 0.523`).
"이 점을 어디로 옮기면 score가 오르나"라는 뜻이고,
이걸 이용해 입력을 거꾸로 최적화하는 게 적대적 예제나 DeepDream입니다.

### zeroGrad가 필요한 이유

`_backward` 들이 전부 `+=` 로 누적합니다.
한 파라미터가 100개 점의 경로에 모두 등장하니 기여분을 다 더해야 진짜 ∂L/∂w 가 나옵니다.
대신 다음 스텝에 지난 값이 남으면 안 되니 backward 단계가 `zeroGrad()` 로 먼저 지웁니다.

## 5. 파라미터에 대한 손실 함수는 연속인가

**연속입니다. 하지만 미분 가능하지는 않습니다.**

`p[5]` 를 4.0 폭으로, 칸 폭 `2e-4` 로 20000칸 훑은 결과:

```
손실   : 이웃 칸 사이 최대 점프 = 7.66e-5   → 칸 폭에 비례. 연속
정답률 : 28회 튐, 한 번에 0.01씩          → 칸을 좁혀도 그대로. 불연속
손실의 꺾임 지점 = 약 250곳                → 연속이지만 매끄럽지 않음
```

연속인 이유는 단순합니다. 덧셈·곱셈·ReLU·max가 전부 연속이고, 연속 함수의 합성은 연속입니다.

### 꺾임의 원인

| 원인 | 어디서 |
| --- | --- |
| `relu(z)` | `z = 0`. 뉴런이 켜짐/꺼짐을 넘나드는 순간 |
| `relu(1 − y·score)` | `y·score = 1`. 점이 마진을 넘나드는 순간 |

증거: 활성화를 tanh로 바꾸니 꺾임이 **250곳 → 27곳**으로 감소.
tanh는 `C^∞` 라 안 꺾이고, 남은 27곳은 hinge loss의 `max()` 때문입니다.

### 꺾임점에서 grad는

미분이 정의되지 않습니다. ReLU의 `z=0` 에서 왼쪽 미분 0, 오른쪽 미분 1.
micrograd는 관례로 하나를 고릅니다.

```js
this.grad += (out.data > 0 ? 1 : 0) * out.grad;   // z=0 이면 0
```

`[0, 1]` 중 아무 값이나 정당한 **subgradient** 입니다.
실무에서 문제가 안 되는 건 `z` 가 정확히 `0.0` 이 되는 일이 부동소수점에서 거의 없기 때문입니다.

### 정답률은 진짜로 불연속

`score` 의 부호가 뒤집히는 순간 점 하나가 통째로 정답/오답을 오갑니다. 계단 함수입니다.
**그래서 정답률로는 학습을 못 합니다.** 미분이 거의 모든 곳에서 0이고, 끊겨 있어서
"어느 쪽으로 가야 나아지나"를 알려줄 수 없습니다.
hinge loss는 이걸 피하려고 쓰는 **대리 손실(surrogate loss)** 입니다.

학습 곡선에서 초록선(정답률)이 계단이고 노란선(손실)이 매끄러운 게 이 차이입니다.

### 일반적으로는

신경망이라고 항상 연속인 건 아닙니다. `argmax`, 반올림, 임계값 비교 같은 이산 연산,
샘플링, 0으로 나누기가 연속성을 깹니다.
딥러닝 구성 요소가 대체로 연속인 건 **역전파로 학습시키려고 일부러 그렇게 고른** 결과입니다.

## 6. 극소가 최소는 아닌데, 어떻게 확신하나

**확신 못 합니다. 보장이 없습니다.**

손실 지형은 볼록하지 않고, 경사하강법이 보장하는 건 기껏해야 정류점입니다.
극소라는 보장도 없습니다 (안장점일 수 있음).

### 실제로 갇힙니다

나선 + 은닉4, 데이터와 설정은 고정하고 **초기값(시드)만** 바꿔 8번:

```
시드 1 → 85%    시드 5 → 72%    시드 8 → 100%
정답률 범위 71% ~ 100%
```

시드 8이 100%를 증명하는데 시드 5는 72%에서 멈췄습니다. 나쁜 곳에 갇힌 겁니다.

### 반대로 여기선 전역 최소를 확인할 수 있습니다

moons + 은닉16, 150스텝 후:

```
데이터 손실(hinge) = 0.0000000000
정규화 손실(L2)    = 0.010284
전체 grad 노름      = 2.028e-3
그중 L2 항의 몫     = 2.028e-3     ← 데이터 항의 grad는 0
```

hinge는 구조적으로 0 이상인데 그 0에 정확히 도달했습니다.
하한을 알고 달성했으니 이건 극소가 아니라 **증명된 전역 최소**입니다.
(일반적인 딥러닝에서는 거의 불가능한 상황입니다.)

남은 grad는 전부 weight decay가 가중치를 0 쪽으로 당기는 힘이고,
가중치가 줄다 어떤 점이 마진 안으로 들어오면 반발합니다. 최소점이 아니라 **평형점**입니다.

### 그래도 실무에서 통하는 이유

**1. 애초에 최소점을 원하지 않습니다** ← 가장 중요

최소화하는 건 훈련 데이터의 손실인데, 원하는 건 처음 보는 데이터에서의 성능입니다.
훈련 손실의 전역 최소는 보통 통째로 외운 상태 = 과적합입니다.
조기 종료(early stopping)는 **일부러 최소점 전에 멈추는** 기법입니다.

**2. 차원이 높으면 나쁜 극소가 드뭅니다**

337차원에서 극소가 되려면 337개 방향 전부가 위로 휘어야 합니다.
하나라도 아래로 휘면 탈출구가 있습니다.
그래서 대부분의 정류점이 극소가 아니라 안장점입니다 (Dauphin et al., 2014).

**3. 파라미터가 넉넉하면 극소들이 비슷해집니다**

moons + 은닉16, 시드만 바꿔 10번:

```
시드 1~10 전부 정답률 100%, 최종 loss 0.009 ~ 0.017
```

도달한 가중치는 매번 다른데 결과는 사실상 같습니다.
반면 은닉4 + 나선은 71%~100%로 흩어집니다.
**용량이 부족할 때 나쁜 극소가 문제가 됩니다.**
과잉 파라미터화가 최적화를 오히려 쉽게 만든다는 게 딥러닝의 반직관적인 부분입니다.

### 쉬운 버전 — 안개 낀 산

손실 = 높이. 안개가 짙어 **발밑 경사만** 보입니다.
grad는 "어느 쪽이 오르막인가"만 알려주고, 반대로 한 걸음 내딛습니다.

반복하면 평평한 곳에 도착하지만, 산 전체에서 가장 낮은 곳인지는 알 수 없습니다.
중턱 웅덩이일 수도 있습니다. 사방이 오르막이라 못 내려가지만 능선 너머에 더 깊은 골짜기가 있을 수 있죠.

다만 ① 애초에 가장 낮은 곳이 목표가 아니고, ② 길이 337개면 막다른 골목이 잘 안 생기고,
③ 웅덩이들이 대체로 비슷하게 깊어서 실무에서는 잘 됩니다.

## 7. 활성화 함수는 무엇을 하는가

흔한 오해 세 가지를 실측으로 정리합니다.

| 오해 | 사실 |
| --- | --- |
| 값이 튀는 걸 막는다 | 목적은 **비선형성**. 없으면 직선밖에 못 그린다 |
| 값을 억제한다 | tanh·시그모이드만. **ReLU는 위로 무제한** |
| 그래서 학습률을 1 이하로 쓴다 | 무관. 강의도 `lr=1.0`을 쓴다 |

### 진짜 목적: 비선형성

활성화 함수를 다 빼고(모든 층 linear) 학습:

```
             활성화 없음    ReLU
moons          93%        100%
circles        64%        100%
xor            67%        100%
spiral         52%        100%      ← 찍기 수준
```

**선형 변환을 아무리 쌓아도 선형 변환 하나**이기 때문입니다. `W₃(W₂(W₁x)) = Wx`.

검증: 16-16-1 을 통과한 함수가 아핀인지 검사 → 오차 `1.78e-15`.
337개 파라미터짜리 3층이 **직선 하나로 붕괴**했습니다.

ReLU는 `z < 0` 을 꺾습니다. 이 꺾임이 층마다 쌓여 구부러진 경계를 만듭니다.
도구에서 은닉 뉴런 hover 시 나오는 **반평면 히트맵**이 그 꺾임 하나이고,
16개를 겹쳐 초승달 모양을 만듭니다.

### ReLU는 값을 억제하지 않는다

```
        은닉 활성값 최대    score 최대    가중치 최대
relu         2.38          3.61         1.22
tanh         1.00          5.08         2.04      ← 은닉값은 1에 갇힘
```

`relu(z) = max(0, z)` 는 위쪽 제한이 없습니다. 입력이 100이면 출력도 100.
tanh만 구조적으로 `[-1, 1]` 에 갇힙니다.

흥미로운 건 tanh 쪽 은닉값이 1로 눌려 있는데 **score는 오히려 더 큽니다(5.08)**.
은닉값이 작으니 보상하려고 가중치가 커진 겁니다(2.04 vs 1.22).
값을 누르면 다른 데서 튀어나옵니다.

tanh가 값을 가두는 건 단점도 됩니다. `|z|` 가 크면 기울기가 0에 수렴해 grad가 사라집니다.
**기울기 소실(vanishing gradient)** 이고, 깊은 망에서 ReLU가 tanh를 밀어낸 이유입니다.

### 학습률과는 무관

```
ReLU  lr=0.5 → 100%      ReLU  lr=2  → 100%
ReLU  lr=1.0 → 100%      ReLU  lr=3  →  95%
```

1을 넘겨도 잘 되고, `lr=2` 가 `lr=0.1`(97%)보다 낫습니다.

값을 가두는 tanh가 오히려 큰 학습률에 강합니다:

```
tanh  lr=10 → 93%  (loss 4.4)      relu  lr=10 → 51%  (loss 416, 발산)
tanh  lr=30 → 90%
```

"활성화가 값을 눌러서 학습률을 낮게 쓴다"가 맞다면 정반대 결과가 나와야 합니다.

**학습률의 한계를 정하는 건 손실 지형의 곡률입니다.**
골짜기가 좁고 가파를수록 작은 걸음이 필요합니다.
`lr < 1` 이 흔한 건 경험적 출발점일 뿐이고,
데이터 스케일·배치 크기·초기화·옵티마이저에 따라 크게 달라집니다.

## 부록: 도구에서 직접 확인하는 법

| 알고 싶은 것 | 하는 법 |
| --- | --- |
| score의 의미 | 데이터 화면의 배경색. 경계 근처는 흐리고 바깥은 진하다 |
| grad가 어디서 오는지 | "부분 스텝"으로 역전파까지 → 출력 쪽 노란 선이 가장 굵다 |
| 활성값 0이면 grad도 0 | 은닉 노드 hover → 히트맵이 까만 뉴런은 노란 선이 거의 없다 |
| `Δw = −lr × grad` | 엣지 툴팁의 grad와 다음 단계의 Δw 비교 |
| 정답률은 계단, 손실은 매끄러움 | 학습 곡선의 초록선 vs 노란선 |
| 나쁜 극소에 갇히는 것 | 나선 + 은닉4로 두고 시드만 1, 2, 3... 바꿔가며 재생 |
| 큰 학습률의 발산 | 학습률 5로 재생 → 손실이 위로 폭발 |
| 활성화 함수의 역할 | ReLU ↔ tanh 전환. 은닉 노드 hover로 경계 모양 비교 |
